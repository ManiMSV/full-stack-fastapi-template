# Implementation Plan: Angular Frontend Migration

**Input**: Feature specification `specs/001-angular-frontend-migration/spec.md`
**Constitution**: `.specify/memory/constitution.md` (v1.1.0)

## Tech Stack

- Angular latest stable (standalone components, signals, new control flow), Angular CLI, Vite-based
- PrimeNG (widgets: forms, tables, dialogs, dropdowns, toasts, password, sidebar behavior) + PrimeNG themes (Aura preset, light/dark variants)
- @tanstack/angular-query for server state
- ng-openapi-gen: generates Angular `HttpClient` services from `frontend/openapi.json`
- Tailwind CSS (custom layout shell only)
- Biome (lint/format, repo-wide), ESLint only if Angular templates require it
- Vitest + @angular/build testing utilities for unit tests
- Playwright (E2E, existing suite reused, selectors updated) + agent-browser for manual/exploratory verification

## Architecture

Big-bang rewrite: fresh `ng new` inside `frontend/`, React sources deleted. Backend untouched.

### Frontend structure (frontend/src/app/)

```
src/app/
  core/          # generated API services, auth service, token interceptor, theme service
  shared/
    layout/      # sidebar shell, header, 404 page
    ui/          # loading, error, empty-state components
  features/
    auth/        # login, signup, recover-password, reset-password pages
    items/       # items list + create/edit/delete
    admin/       # user table (sort/search/paginate) + user add/edit/delete
    settings/    # profile, password, appearance
    dashboard/   # post-login landing
```

### Routing

- Angular Router, lazy-loaded feature routes
- Auth guard on protected routes; redirect to `/login` when unauthenticated
- Wildcard route -> 404 component
- Route map: `/login`, `/signup`, `/recover-password`, `/reset-password`, `/dashboard`, `/items`, `/admin/users`, `/settings`, `/` (redirect)

### State & data flow

- Token: persisted in `localStorage`, attached via HTTP interceptor, cleared on 401 (redirect to login)
- Server state: TanStack Angular Query (queries for items, users, pending counts; mutations for create/update/delete; invalidate on change)
- Client state: signals for theme (light/dark, persisted), auth session

### API client

- `ng-openapi-gen` consumes `frontend/openapi.json` (regenerated by `scripts/generate-client.sh`)
- Output `src/app/core/api/`; `generate-client` npm script replaced
- Existing `src/client/` (Hey-API) deleted; `openapi-ts.config.ts` removed

### Testing

- Unit (Vitest): auth service (token storage, guards), theme service (toggle + persistence), one CRUD feature (items)
- E2E (Playwright): existing 8 spec files preserved; update selectors/DOM expectations for PrimeNG; auth.setup.ts and config.ts updated in foundational phase
- agent-browser: manual verification pass before sign-off (per constitution)

### Build & deployment

- Angular build output `frontend/dist/<project>/browser`; update frontend Dockerfile (nginx) to new output path and SPA fallback
- `compose.yml` and CI workflows updated only where frontend build/test commands change

## User Story Mapping

| Story | Priority | Key work |
|-------|----------|----------|
| US1 Authentication | P1 | login, signup, recover, reset, guard, token persistence |
| US2 Items CRUD | P1 | items list + create/edit/delete + validation |
| US3 Admin users | P2 | sortable/searchable/paginated table, add/edit/delete |
| US4 Settings | P2 | profile, password, appearance/theme |
| US5 Shell & dashboard | P2 | sidebar pending counts, dashboard, 404, responsive |

## Risks

- PrimeNG dark mode = theme switching via CSS variables; verify early (foundational spike)
- E2E selector rewrites for PrimeNG dialogs/dropdowns; budget per-story
- Vitest + Angular: verify `ng test` integration in setup before relying on it
- Docker output path change breaks nginx unless updated in polish phase

## Definition of Done

- All 8 Playwright spec files pass
- Vitest unit tests for auth, theme, items pass
- Biome lint + typecheck green
- Docker image builds and serves SPA
- agent-browser verification pass signed off
- Constitution v1.1.0 spec compliance check completed at each checkpoint
